# Deep Code Reader

[English](README.md)

**把代码库转化为可复用的 AI 知识技能，以源码为依据，通过考试验证，服务于查询和参考。**

---

## 问题

LLM 阅读代码时的默认行为是浏览和概括。让它"理解"一个仓库，你只会得到一份泛泛的概述，一旦问到具体问题就露馅。下次再问，又得从头搜索。

## 解决方案

Deep Code Reader 产出的是**经过验证的认知技能** —— 结构化的知识文档，AI 加载后就能像真正读过代码的人一样工作。

### 工作流程

```
扫描仓库 → 识别模块和依赖关系 → 你选择要读的模块
                          ↓
            逐模块：精读源码 → 生成 skill
                          ↓
                 闭卷考试验证（ABC 循环）
                          ↓
         Agent B（读代码，不看 skill）→ 出考题 + 标准答案
         Agent C（看 skill，不读代码）→ 闭卷答题
                          ↓
              回归通过 → 独立最终验收 → 下一模块
              任一考试失败 → 修补 → 累计回归
                          ↓
              生成全局索引 + 与你进行问答验收
```

工具先扫描仓库结构和依赖关系，让你选择要深读的模块。每个模块生成的技能都经过**累计闭卷回归和独立最终验收**，评分前先核对源码证据。通过记录的是特定源码版本下已测试的问题覆盖范围；最多三轮后仍有缺口，会明确报告。

## 让你的 Token 在你睡觉时学习

大多数订阅套餐包含约 5 小时的每日 AI 算力额度，夜间大量闲置。Deep Code Reader 把这些空闲额度变成积累的知识。

睡前启动，醒来就有一整套经过验证的技能可以加载。跑的仓库越多，你的 AI 懂的就越多 —— 利用夜间额度，零额外成本持续积累。

## 快速开始

### 安装

把 `deep-code-read` 目录添加到你的 agent 技能目录：

```bash
git clone https://github.com/CiferaTeam/deep-code-reader.git
cp -r deep-code-reader/deep-code-read ~/.claude/skills/
```

**技能创建：** 优先使用宿主 Agent 内置的 Skill Creator 或技能编写规范；未提供时，直接按照工作流自带模板生成。

### 使用

```bash
# 从 GitHub URL
/deep-code-read https://github.com/example/project ~/.claude/skills/

# 从本地仓库
/deep-code-read ./path/to/project ~/.claude/skills/
```

就这么简单。工具全自动运行，只在两个地方暂停等你确认：

1. **确认版本** — 要分析的 tag/分支
2. **选择模块** — 要深读的模块

## 产出物

```
~/.claude/skills/
  project/                      # 克隆的源码（仅 URL 模式）
  project-dr/                   # 全局索引技能
    SKILL.md
  project-dr-auth/              # 模块技能
    SKILL.md
    reference.md                # 复杂模块可选
  project-dr-routing/
    SKILL.md
  ...
```

### 每个模块技能覆盖 5 个维度：

| 维度 | 内容 |
|---|---|
| **职责与能力** | 模块做什么，公开 API，函数签名 |
| **核心设计逻辑** | 为什么这样设计，关键架构决策 |
| **数据结构** | 核心类型、接口及其关系 |
| **状态流转** | 数据如何流动，入口点，错误处理路径 |
| **修改指南** | "要改 X 功能，需要动这些文件" |

### 全局索引技能包含：

- 仓库来源、版本号、跟踪分支
- 所有模块及一句话描述
- 模块间依赖关系图
- 跨模块场景指南

## ABC 验证循环

这就是 deep-code-reader 区别于"又一个代码摘要工具"的核心：

- **Agent A**（主模型）：读源码，生成技能文件
- **Agent B**（按代码理解准确性选模型）：读源码但不看技能，出题并为答案中的每个必要事实附上源码证据
- **Agent C**（主模型）：只看技能文件，闭卷答题

协调者先逐项核对标准答案的源码证据，再进行评分。每轮都重测**全部累计题库**，包括此前通过的题目，并补充新题。回答须覆盖必要事实，且没有实质性错误或矛盾。

回归全部通过后，冻结文档，由全新 B 生成关于机制、限制和实际参考场景的**独立最终验收题**。全新 C 只接收技能文档及题目正文与 ID。同一版文档必须通过两项考试；失败的最终验收题进入回归题库，修补后的最终验收使用新题。

每个模块最多 3 轮，包含初始候选版本。未解决的缺口或证据争议会明确呈现，并阻止验证通过。记录包含源码 commit、文档哈希、源码证据、两项考试各自的成绩及隔离级别。仅靠提示词隔离时标记为 `partial_validated`；`verified` 需要权限隔离或经过检查的访问日志。通过表示已测试范围内的知识通过验证。

## 生成完成后

工具进入**问答验收阶段**：

- 随意提问，AI 仅凭生成的技能回答
- 如果不知道问什么，Agent B 生成的推荐深度问题可供参考
- 如果仅凭技能答不出来，这就是一个诚实的差距信号

## 平台支持

Deep Code Reader 不绑定特定平台。只要 AI 编程 agent 支持以下特性即可使用：

- 技能/指令文件加载
- 子代理调度
- 文件系统读写

已在 Claude Code 上测试通过。理论上兼容 Codex、Gemini CLI 及其他支持 skill 的 agent。
